# SoC-all-core

Six crypto SoCs for the AMD/Xilinx ZCU102 that share one Vivado block design and differ
only in the CPU. Every SoC runs the same firmware and testbenches on the same AES-128,
SHA3-256 and RSA-2048 accelerators, so the CPUs can be compared on equal terms.

| Project | CPU | CPU block in the diagram |
|---|---|---|
| [`socs/rissp_soc`](socs/rissp_soc) | RISSP, original (35 instructions) | `rissp_top_0` |
| [`socs/rissp_v2b_soc`](socs/rissp_v2b_soc) | RISSP v2b: 9 instructions, one hardware block per instruction type | `rissp_v2b_0` |
| [`socs/rv32i_soc`](socs/rv32i_soc) | RV32I 5-stage pipeline (`rv32i_ultra`) | `rv32i_0` |
| [`socs/ibex_soc`](socs/ibex_soc) | lowRISC Ibex (RV32M disabled) | `ibex_core_0` |
| [`socs/rocket_soc`](socs/rocket_soc) | Rocket, small RV32 configuration from Chipyard | `rocket_0` |
| [`socs/cva6_soc`](socs/cva6_soc) | OpenHW CVA6, `cv32a6_imac_sv0` | `cva6_0` |

## Block design

```
                    clk_wiz_0 (100 MHz in, 40 MHz out)    proc_sys_reset_0
                                   |
 blk_mem_gen_0  <-- imem --  CPU (cpu_core) -- m_axi (AXI4-Lite) --> axi_interconnect_0
 (instruction ROM, .coe)                                              |  M00  aes_axi_slave_0      AES-128
                                                                      |  M01  SHA3_hardware_new_0  SHA3-256
                                                                      |  M02  RSA_mark03_0         RSA-2048
                                                                      |  M03  axi_bram_ctrl_0 + blk_mem_gen_1 (debug BRAM)
                                                                      |  M04  axi_uartlite_0
```

Each CPU sits behind a wrapper `cpu_core` with the same ports (`clk`, `rst_n`,
`imem_addr`, `imem_rdata`, `m_axi_*`), so the six block designs are identical except for
that one cell. The CPU and the accelerators enter the block design as module references
(plain RTL, no packaged IP), which also makes the projects independent of the FPGA family.

| Slave | Base address | Range |
|---|---|---|
| AES | `0x4000_0000` | 16 KB |
| SHA3 | `0x4400_0000` | 64 KB |
| RSA | `0x4800_0000` | 64 KB |
| UART | `0x4060_0000` | 64 KB |
| Debug BRAM | `0xC000_0000` | 8 KB |

The instruction ROM is 8192 x 32 bit, read with one cycle of latency, and holds the test
firmware (`firmware/<test>.coe`).

## Quick start

Requirements: Vivado 2024.2 or newer (the projects were developed on 2025.2) with the
Zynq UltraScale+ device `xczu9eg-ffvb1156-2-e` installed.

1. Clone the repository:
   ```
   git clone https://github.com/thanhtruong332/SoC-all-core.git
   ```
2. In the Vivado Tcl console, build the project of one SoC (2 to 15 minutes, CVA6 is the slowest):
   ```
   source <repo>/socs/rissp_soc/create_project.tcl
   ```
   The script creates `socs/rissp_soc/rissp_soc.xpr`, builds the block design and prints
   `rissp_soc: project ready`. Sourcing it again later only opens the project.
3. Pick a test and simulate:
   ```
   set_test aes_ecb
   ```
   then Flow Navigator > Run Simulation > Run Behavioral Simulation. The testbench prints
   `[PASS]` or `[FAIL]` and the cycle counts.
4. Run synthesis and implementation from the Flow Navigator as usual.

Options, set before `source`:

| Command | Effect |
|---|---|
| `set core_soc_part <part>` | build for another part (default `xczu9eg-ffvb1156-2-e`) |
| `set core_soc_rebuild 1` | delete the generated project files of that SoC and build it again |

## Tests

| `set_test` | Testbench | Firmware |
|---|---|---|
| `aes_ecb`, `aes_cbc`, `aes_cfb`, `aes_ctr` | `tb_aes_*` | AES-128 in the four modes |
| `sha3`, `sha3_4`, `sha3_16` | `tb_sha3*` | SHA3-256 of 1, 4 and 16 blocks |
| `rsa2048` | `tb_rsa2048` | RSA-2048 modular exponentiation |
| `rsa2048_fast` | `tb_rsa2048` | RSA-2048 with the fast path for e = 65537 |
| `rsa` | `tb_rsa` | old 32-bit RSA register map; ends in TIMEOUT on these SoCs |

The testbenches check the results against known answers (NIST vectors for AES) and do
not depend on the CPU, so the same files serve all six SoCs.

## Repository layout

```
socs/<name>_soc/
    create_project.tcl   builds the Vivado project of that SoC
    filelist.f           the same RTL as a plain file list (simulation view)
rtl/
    accelerators/aes, sha3, rsa         AXI4-Lite crypto accelerators
    cpu/<core>/                         CPU RTL and its cpu_core wrapper
    cpu/common/                         AXI4 to AXI4-Lite bridge, ROM bridge (Rocket, CVA6)
    cpu/rocket/generated/               Rocket Verilog generated by Chipyard (CIRCT)
third_party/                            CVA6, pulp-platform axi and common_cells (used files only)
tb/                                     testbenches
firmware/                               test programs: assembly source and .coe ROM image
constraints/soc.xdc                     timing exceptions for the reset and UART ports
scripts/set_test.tcl                    the set_test command
docs/                                   notes on the Vivado flow, Vietnamese guide
```

Vivado writes its project files next to the script (`socs/<name>_soc/<name>_soc.*`);
`.gitignore` keeps them out of the repository.

## Notes

  [docs/VIVADO_NOTES.md](docs/VIVADO_NOTES.md).

  default), run implementation and read WNS. Estimate: fmax = 1000 / (period in ns - WNS).
